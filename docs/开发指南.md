# MediaFlow 开发指南

## 原则

- 不依赖付费服务、自建服务器或商业媒体 API。
- Parser、DownloadManager、持久化、UI 和平台代码保持独立。
- 自动化测试不得访问真实平台或用户文件。
- 新平台通过实现 `ParserInterface` 接入，不修改通用 UI。

## 目录

- `lib/app/`：应用启动、路由、主题和导航 Shell。
- `lib/core/`：配置、日志、缓存、存储和通用模型。
- `lib/features/parser/`：平台检测和解析器。
- `lib/features/downloader/`：下载队列、续传、文件保存和历史持久化。
- `lib/features/settings/`：本地设置模型、Repository 和页面。
- `lib/features/about/`：版本、项目地址和协议说明。
- `test/`：领域、Repository、网络、文件和 Widget 测试。

## 本地验证

```powershell
flutter pub get
flutter analyze
flutter test
flutter build windows --release
```

Windows 构建使用 Flutter 插件时需要开启 Windows 开发者模式，以允许创建符号链接。

## 数据文件

应用支持目录下保存：

- `settings.json`
- `download_history.json`
- `logs/parser.log`
- `logs/downloader.log`
- `logs/network.log`
- `logs/error.log`

修改持久化模型时，应保持旧字段缺失时的默认值，并增加升级测试。

## 发布前检查

1. 确认 `dev` 工作区干净且与远端同步。
2. 执行静态分析、完整测试和目标平台构建。
3. 检查仓库中不存在密钥、Token、私人路径或本地配置。
4. 更新版本、README、CHANGELOG 和使用说明。
5. 从 `dev` 合并到 `main` 前进行人工验收。
