# MediaFlow 开发计划

## 项目定位

MediaFlow 是一个长期维护的跨平台媒体链接处理工具，首要目标平台为 Windows，随后扩展到 Android 和 iOS。

## 开发环境

为控制 C 盘占用，开发工具与缓存统一使用 D 盘：

| 项目 | 路径 |
| --- | --- |
| Flutter SDK | `<development-drive>\dev\flutter` |
| Flutter 项目 | `<development-drive>\projects\mediaflow` |
| Pub 缓存 | `<development-drive>\dev\cache\pub` |
| Gradle 缓存 | `<development-drive>\dev\cache\gradle` |
| 临时文件 | `<development-drive>\dev\tmp` |
| Android SDK（后续） | `<development-drive>\Android\Sdk` |

Android 开发将使用真机 USB 调试，不安装 Android Emulator 或 System Image。

## 架构

项目采用 Feature-first Clean Architecture 与 MVVM 的组合：

- `app/`：启动、路由、主题和应用级 Shell。
- `core/`：配置、模型、接口、错误、日志、网络、持久化等基础能力。
- `features/`：按用户能力拆分，并在功能内逐步引入 `data`、`domain`、`presentation`。
- `platform/`：后续放置媒体平台解析器、下载引擎和自动更新适配器。

阶段 3 前已建立 `AppConfig`、`MediaLink`、`MediaInfo`、`DownloadTask`，并定义 `MediaResolver`、`MediaResolverRegistry` 与 `DownloadService` 接口；具体实现仍为空。

新媒体平台将实现独立解析器并注册到平台注册表，避免修改页面和下载任务核心流程。

已完成：Windows Release 构建、启动验证与 Git 初始提交。

### 阶段 3：核心功能

#### 阶段 3.1：媒体链接处理基础框架（已完成）

- 新增 `features/parser` 的 presentation、domain、data 分层。
- 校验 http/https URL，并显示错误提示。
- 识别抖音、Bilibili 与未知平台。
- 有效链接显示平台和等待解析状态；未接入真实媒体解析。

#### 阶段 3.2：媒体解析模块架构（已完成）

- 新增 VideoInfo、ParserResult 与 ParserInterface 作为唯一解析领域契约。
- 新增 BilibiliParser、DouyinParser 空实现，均不执行网络请求。
- 链接状态保存 selectedPlatform 与 parserStatus。
- 移除旧的 core MediaInfo / MediaResolver 占位契约，避免模型重复。

#### 阶段 3.3：模拟解析闭环与视频信息展示（已完成）

- 新增 application/ParserService，串联平台检测、解析器选择和 ParserResult。
- Bilibili/抖音解析器返回固定模拟 VideoInfo，不执行真实网络请求。
- 首页展示封面占位、标题、作者、平台、时长与解析状态。
- 状态流覆盖等待输入、等待解析、解析中、成功和失败。

#### 阶段 3.4：下载系统基础架构（已完成）

- 新增 features/downloader 的 domain、data、application、presentation 分层。
- DownloadManager 使用 Riverpod 管理多个内存任务。
- 模拟进度按 0%、20%、40%、60%、80%、100% 更新。
- 首页可创建模拟下载任务，下载记录页显示标题、平台、进度和状态。
- 不请求真实资源，不写入任何文件。

#### 阶段 3.5：真实媒体解析架构（已完成）

- 新增独立 `core/network` 网络客户端，平台解析器可注入并可替换。
- Bilibili 支持普通链接和短链接，获取公开标题、作者、封面、时长与视频信息。
- 抖音支持分享链接重定向，并合并内嵌数据、JSON-LD 和 Open Graph 元数据。
- 统一网络错误、链接失效、平台不支持和解析失败状态。
- 自动化测试完全使用离线响应夹具，不请求真实媒体资源。
- 下载模块保持模拟状态，未进入真实下载。
