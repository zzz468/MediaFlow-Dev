# 下载模块

## 当前能力

阶段 4.1 在现有 `DownloadManager` 上完善真实下载队列：

1. 接收解析器提供的直接媒体地址和必要请求头。
2. 使用流式 HTTP 请求读取媒体字节，不一次性载入内存。
3. 持续更新已接收字节、总大小和下载进度。
4. 先写入 `.part` 临时文件，成功后再重命名为最终文件。
5. 下载失败或任务被删除时清理未完成文件。
6. 完成后记录最终保存路径。

当前可以创建多个真实任务，并按加入顺序逐个执行。活动任务可以暂停，继续时根据 `.part` 文件实际长度发送 HTTP Range 请求。模拟下载能力继续保留。

## 分层结构

- `domain/`：`DownloadTask`、下载事件、统一异常和 `DownloadService` 接口。
- `data/`：流式 HTTP 客户端、本地文件存储和真实下载服务。
- `application/`：`DownloadManager` 负责任务状态和单任务约束。
- `presentation/`：展示进度、字节大小、失败原因和保存路径。

## 保存目录

- Windows 等桌面平台：系统下载目录下的 `MediaFlow` 文件夹。
- Android 和 iOS：应用文档目录下的 `MediaFlow` 文件夹。
- 如果桌面系统无法提供下载目录，则回退到应用文档目录。

文件名会移除跨平台不允许的字符，已有同名文件时自动增加序号。下载目录自定义将在后续设置模块实现。

## 安全边界

- 只下载解析器明确标记为可用的直接媒体地址。
- HTML、JSON 等非媒体响应会被拒绝，避免把网页误存为视频。
- 不绕过登录、权限、地区限制或平台安全机制。
- 当前支持顺序队列和断点续传，不支持多线程并行、批量导入或下载加速。
