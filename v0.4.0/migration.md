# v0.4.0 兼容迁移计划

**规划，尚未实施。** v0.3.0 的 `download_history.json` 仍是 `DownloadTask` JSON 数组；现有新字段可选，旧任务可读取。v0.4.0 不预设数据库迁移，也不清空或重建用户数据。

1. 首先以 v0.2.0、v0.3.0 与新旧混合 History 夹具锁定读取结果，包含独立视频、双图聚合、部分成功、文件不存在和重启恢复。
2. 若实测证明图片以外的作品需要聚合，先定义显式作品/操作/资源关系的可选字段与旧任务回退规则；不能仅通过标题或短时资源 URL 推断同一作品。旧图片任务继续按原规则展示，旧视频仍独立。
3. 新内容 Parser 成功应返回 `ParserContentSuccess(MediaContent)`；既有 Bilibili/Douyin 视频 `ParserSuccess(VideoInfo)` 保持可用。不能伪造 `videoUrl` 表示图文。
4. 每个资源仍对应独立任务，保留暂停/继续、Range、`.part`、失败重试、文件名避让和已完成文件。作品状态从任务真实状态推导，不假定整批原子成功。
5. Windows 保留本地路径；Android 现有 MediaStore 历史路径语义不得无迁移改成 `content://`。任何持久化变化先做旧数据读写和真机文件访问验证。

只有当阶段 2 确定新增 production 内容，并由具体用例证明已有合同不足时才实施对应迁移；规划文本不构成修改源码的授权。
