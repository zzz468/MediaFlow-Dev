# v0.4.0 第二阶段与平台研究执行规则

状态：**研究规则与计划；尚未形成 v0.4.0 新的实测结论，Douyin 图文尚未满足 production 门槛。** 本文件与根目录 `AGENTS.md` 同时执行；冲突时以 `AGENTS.md` 为准。优先复核 [v0.3.0 Douyin 图文调查](../../v0.3.0/research/douyin-gallery-source.md)，但旧样本、旧请求结果及第三方项目声明都只是线索，不能代替当前双端实测。

2026-09-27 产品所有者定版：匿名优先，允许必要本地signer/正常客户端上下文；有证据表明平台要求时允许用户主动在App自有隔离profile登录的本地session fallback。旧匿名-only研究范围不构成永久产品禁令。Browser Observation保留fallback/debug，不恢复主路线。规则差异、UIFID证据和下一实验见[poc/uifid-context-audit.md](poc/uifid-context-audit.md)。

## 研究顺序与范围

1. 主动调查多个仍有维护迹象的 GitHub / 开源项目，覆盖 Douyin 图文、Bilibili 图文、多资源解析和下载、单资源失败重试、History 聚合与重启恢复，以及后续平台适配。非官方实现可以作为可行性线索，不因缺少官方文档直接排除。
2. 逐个核对 LICENSE、维护状态、关键源码、数据入口、请求参数、内容类型判断、资源字段与顺序、下载 URL 选择、失败降级、账号或会话依赖、浏览器/平台依赖、远程服务和高风险依赖。用[参考项目记录模板](reference-project-template.md)在本目录留下可追溯记录。没有核实的字段写“未核实”，不能从 README 的“支持”推断匿名可用。
3. 对比至少两条独立实现或数据路线；如果多个项目走同一路径，要区分平台真正要求的条件与项目自己的实现选择，找出 MediaFlow 能独立复现的最小路径。第一条路线失败后，继续检查其他成熟项目和公开入口；记录已排除路线及证据。
4. 在独立 PoC / 测试中有限验证，再分别验证 Windows 和 Android。记录请求时间、测试环境、公开作品 ID、响应结构摘要、图片数量与顺序、匿名资源请求、MIME、实际下载结果和链接时效。不保存用户 Cookie、Token、凭据、媒体响应正文或不必要的个人数据。
5. 只有满足下述准入条件，才修改 production Parser；接入后再做旧功能回归和两端 Release GUI 真实验收。研究成功、PoC 成功、Debug 成功、构建成功和 production 验收是不同状态，须分别记录。

研究可以借鉴思路、数据流、接口、字段映射和模块边界。直接复用代码前必须确认许可证允许，并记录仓库、LICENSE、原文件、复用片段、改动、归属声明和对分发的影响；许可证缺失或不兼容的代码不得复制。即使只独立复现思路，也应注明来源、MediaFlow 的差异和未复用代码。第三方实现不得把平台特例带入公共 ParserService、Downloader、History 或领域模型。

## Douyin 图文证据清单

至少用多个来源交叉核对：分享链接到作品 ID 的路径、图文类型字段、图片列表字段和顺序、匿名数据入口、签名是否必要、Cookie 是可选还是实际必要、浏览器环境需求、图片直链匿名下载、稳定 fallback，以及 Windows / Android 能否独立复现。可研究公开页面、匿名客户端接口和本地 Browser Adapter；签名算法可作为候选，但能本地计算签名不等于入口匿名可用。

选择明确公开且授权访问的多图作品，先证明取得**目标作品的结构化结果**，再按作品内出现位置确认图片资源；相同 URL 若代表不同位置，不按 URL 去重。至少两张图片要分别取得直链并真实下载，核对响应 MIME、文件类型、大小及可打开性。Windows 与 Android 各自留下同等证据；一个平台的成功不能替代另一平台。若某路线被登录、验证码、WAF、安全挑战、付费、地区或权限限制拦住，安全停止该路线，并检查其他合规公开入口。

只有以下条件**全部满足**，Douyin 图文才可进入 `Parser → MediaContent → MediaResource → Downloader → History` 的 production 开发：

1. MediaFlow 自己取得目标作品的结构化图文结果，并确认图片资源及顺序。
2. 至少两张真实图片直链按所声明的访问模式取得并实际下载，内容与 MIME 经核对。声称匿名支持时必须无登录；条件session fallback须有必要性证据、主动授权、隔离存储及清除/失效验证，不用登录结果冒称匿名成功。
3. Windows 和 Android 分别独立复现上述过程。
4. 全链本地实现，不依赖第三方解析服务器、外部浏览器 Cookie / Token 导入导出、验证码或 WAF 绕过、访问控制绕过。用户主动登录的App自有本地会话仅作为证据支持的条件fallback，凭据只在平台Adapter内部使用，不能泄露到公共模型/日志/History/Crash report。
5. 平台字段与请求逻辑局限于 Douyin Parser / Adapter；可映射到既有 `MediaContent` / `MediaResource` 和通用下载、History 语义，并有离线异常契约与双端 Release GUI 验收方案。
6. 满足根目录 `AGENTS.md` 的隐私、许可证、依赖和五端架构约束。

关键条件未满足时标记 `researched but not production-supported`，继续保存可复查的研究成果，供 v0.5.0 或后续版本复核；不宣称已支持，也不将“本版暂不接入”写成永久放弃。研究结论必须说明哪些是源码线索、哪些是 MediaFlow 自测、哪些仍未验证。

## 安全与现有能力保护

本地处理、隐私优先、零自建或第三方解析服务器；不代理用户流量、不 MITM、不导出 Cookie / Token、不读取其他 App 登录态、不伪造用户身份。可以分析第三方项目为何成功，并记录其登录、令牌重放、安全挑战或远程服务依赖；凭据重放、挑战求解、远程解析不得进入production。匿名优先；必要时可用用户主动授权的App自有本地会话，不将公开内容解析扩展成无授权账号操作。正常签名/上下文兼容与安全绕过逐项区分，按根AGENTS.md有限实验和安全停止。

新入口适配统一内容模型，不另造下载系统。保护已发布并验收的 Bilibili 视频/图文、Douyin 视频、`MediaContent` / `MediaResource`、多资源下载、单资源重试、History 聚合与重启恢复，以及 Windows / Android 行为。任何 production 修改须通过对应回归。Android 真机安装前须按 `AGENTS.md` 第三十条检查现有应用、包名、签名和数据安全。

## 研究记录的最低要求

每个重点项目各有记录：仓库地址、LICENSE 证据、最近维护状态、关键实现文件、数据获取路线、登录/Cookie/Token/签名/浏览器/服务器依赖、Windows/Android 可行性、MediaFlow 是否采用及原因、思路参考或代码复用、独立实测证据与未验证项。路线比较页应交叉列出必要条件、项目选择、排除理由和下一项最小验证。不要只把调查结果留在终端。
